# CKTV 客户端

把 CKTV 站点装进 macOS、Windows、Linux、Android 和 iOS 应用里。启动时自动测速选出最快的线路，带自动检查更新，还能把视频下载到本机离线播放。

界面是纯静态页面（无框架），原生层是 Tauri 2（Rust）。站点内容仍由服务器提供；只有用户自己点「下载」的视频才会保存在本机。

## 下载和安装

每次发布都会有新的版本号。最新版本和全部安装包都在 Release 页面：

- **最新版本（全部安装包）**：<https://github.com/1837620622/ck_tv/releases/latest>
- **构建记录（Actions）**：<https://github.com/1837620622/ck_tv/actions/workflows/app-release.yml>
- **固定地址（永远指向最新版）**
  - 应用读取的更新清单：<https://github.com/1837620622/ck_tv/releases/latest/download/update.json>
  - iPhone 的 AltStore 源：<https://github.com/1837620622/ck_tv/releases/latest/download/altstore.json>

安装包文件名里的 `<版本>` 是版本号，例如 `1.2.0`。

| 平台                             | 在最新版本页面里找           | 怎么安装                                                                                                                     |
| -------------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| macOS（Apple 芯片和 Intel 通用） | `CKTV_<版本>_universal.dmg`  | 打开 `.dmg`，把 CKTV 拖进「应用程序」。第一次打开提示「无法验证开发者」时，到「系统设置 → 隐私与安全性」底部点「仍要打开」。 |
| Windows                          | `CKTV_<版本>_x64-setup.exe`  | 运行安装程序。SmartScreen 提示时点「更多信息」→「仍要运行」。                                                                |
| Linux                            | `CKTV_<版本>_amd64.AppImage` | 加上执行权限（`chmod +x`）后直接运行。                                                                                       |
| 安卓                             | `CKTV_<版本>_android.apk`    | 允许安装未知来源的应用后安装。之后的版本直接覆盖安装。                                                                       |
| iPhone / iPad                    | 不能直接安装                 | 见下一节。                                                                                                                   |

最低系统版本：macOS 11、iOS 14。

## iPhone 和 iPad

先说原则：本项目不花钱、不上架 App Store。苹果不允许未签名的应用直接安装，所以 iPhone 上没有「下载安装包就能装」的办法。下面按推荐顺序来，选一个就行。

### 方式一：网页添加到主屏幕（推荐，免费、永不过期）

适合：只在线看，不需要离线下载。

步骤：

1. 用 Safari 打开站点：https://tv.chuankangkk.top
2. 点底部分享按钮 →「添加到主屏幕」。
3. 主屏幕上会出现 CKTV 图标，点开就是全屏的网页版。

能用：在线播放、全屏、切换线路。
没有：离线下载、应用内更新提示（新版本去发布页看）。

### 方式二：SideStore 或 AltStore 自签安装（免费，要离线下载才用它）

适合：需要在手机上离线下载视频。

原理：用你自己的免费 Apple ID 给 IPA 签名再安装，不经过 App Store，也不花钱。SideStore 和 AltStore 装的是同一个 IPA，装好之后运行速度没有差别，区别只在续签方不方便：

- SideStore（首选）：装好后手机自己在后台续签，不用电脑，只需要一台电脑做一次初始安装。
- AltStore：续签要连一台开着 AltServer 的电脑（同一 Wi-Fi），适合电脑常在身边的用户。

步骤（SideStore）：

1. 在电脑上用 SideStore 的安装工具（iLoader）把 SideStore 装到手机上，并装好 LocalDevVPN，按提示连上。
2. 在 SideStore 里添加源：https://github.com/1837620622/ck_tv/releases/latest/download/altstore.json ，或者直接下载发布页里的 `CKTV_<版本>_ios-unsigned.ipa` 再导入。
3. 点安装，装好就能用，离线下载也在里面。

免费账号的限制（苹果定的，不是本项目定的）：

- 签名 7 天过期：过期后应用打不开，但不会被删除，续签一次就恢复；SideStore 会在后台自动续签。
- 同时只能装 3 个自签应用（SideStore/AltStore 自己也占一个名额）。

版本注意：SideStore 用 0.7.0-alpha（2026 年 9 月 15 日发布，修了苹果那边改动导致的登录失败），不要用标了「不要用」的 0.6.4；iOS 26.4 及以上要用 iLoader 重装；iOS 27 请先看 SideStore 最新 release notes 再动手。

### 性能说明

- 在线播放：网页版和客户端都用系统 WebView 播，画质和流畅度没有本质差别，不用为了「更快」去折腾自签。
- 客户端真正多出来的性能收益是两处：启动时测速选最快的线路（开播更快、卡顿更少），以及离线下载后本地播放（完全不受网络波动影响）。
- 自签工具只影响安装和续签，不影响装好后的运行速度。

## 离线下载（电脑和手机都有）

- **从网页下载**：站点在播放视频时，左下角工具条会多出「下载本集」和「列表」（手机上在底部导航栏上方）。点「下载本集」**直接在后台开始下载**，不用离开正在看的页面，按钮显示「已开始下载」，进度在菜单的「下载管理」里看。
- **下载结果是一个能直接播放的 MP4**：分片视频（`.m3u8`）下载完后自动合成一个 `.mp4`（只换封装、不重新编码，画质不变，几秒钟），删掉分片。fMP4 分片直接拼接成 MP4。分片里是 H.265 等暂不支持合成的编码时，保留分片，应用内照样能播放。
- **手动粘贴**：下载页的「视频地址」可以粘贴 `.mp4` 直链，也可以粘贴 `.m3u8` 分片地址。分片视频自动选最高画质，最多 4 个分片同时下载，AES-128 加密的分片在本机解密。SAMPLE-AES 等 DRM 加密不支持，会直接报错，不会留下残缺的文件。
- **保存位置**：应用自己的数据目录，不进入系统相册、「文件」或下载文件夹。卸载应用时一并删除。
- **播放**：下载页里可以播放并全屏。电脑上还能用系统播放器打开，手机上没有这个入口。
- **手机**：下载页在主窗口里打开，顶部有返回按钮，返回后回到原来看的视频。
- **限制**：地址最长 8192 个字符，只接受 `http://` 和 `https://`。播放列表最大 4 MB，单个分片最大 64 MB，分片最多 2 万个。失败或取消的可以「重新下载」。删除要点两次，避免误删。
- 只保存你有权保存的内容。

## 安全模型

- 站点页面是远程内容，**不能调用任何原生命令**。它只能通过 `cktv://` 地址请求应用做下面几件事，其它地址一律忽略：

  | 地址                                                   | 作用                                                         |
  | ------------------------------------------------------ | ------------------------------------------------------------ |
  | `cktv://updater`（可加 `?tab=update\|servers\|about`） | 打开更新中心                                                 |
  | `cktv://home`                                          | 回到启动页                                                   |
  | `cktv://resume`                                        | 切回前台时检查更新（距离上次检查超过 30 分钟，才真的去检查） |
  | `cktv://downloads`                                     | 打开下载列表                                                 |
  | `cktv://download?url=…&title=…[&nonce=…&sig=…]`        | 带有效的一次性签名时直接开始下载；否则只打开下载页并填好地址 |
  | `cktv://browser?url=…`                                 | 用系统浏览器打开当前页面；**只接受线路列表里的站点地址**     |

- **只有用户真的点了「下载本集」才会直接开始下载**。站点页面的内容不可信，不能让它替用户写文件：应用每次启动生成一个随机密钥，只写进注入脚本的闭包里（站点自己的脚本读不到）；用户真的点击（`event.isTrusted`）时，注入脚本对「动作｜视频地址｜随机数」做 HMAC-SHA256 签名，原生层验证签名，并且每个随机数只认一次（截获了也不能重放）。没有签名或签名不对的请求，仍然只打开下载页、填好地址，由用户确认（见 `src-tauri/src/action_key.rs`）。
- 站外链接交给系统浏览器打开，不在应用里跳转。
- 注入脚本只在应用的 WebView 里运行，站点源码不因此改动；界面放在 Shadow DOM 里，不影响站点自己的样式。
- 原生命令 `open_external` 和更新清单里的下载地址，只允许 `github.com`、`objects.githubusercontent.com`、`release-assets.githubusercontent.com`、`tv.chuankangkk.top`、`ck-tv.pages.dev` 及其子域名，并且必须是 `https://`。
- 线路只能是 `https://` 的官方线路或用户添加的线路（调试版额外允许 localhost，方便联调）。
- 应用不替换自己：更新只是提示和下载链接，安装包由用户自己安装。Release 说明里有每个安装包的 SHA-256，下载后可以核对。

## 启动与开场

只有一段开场，约 1 秒：

- **启动页**（`src/index.html`）：居中的品牌组（网站标志和站名「CKTV-传康播放器」，和网站顶栏一样，画在同一张 SVG 里）＋ 一条细进度条 ＋ 一行状态。圆环描边、播放三角弹出、字标上浮；底部写明「非盈利 · 免费 · 无偿提供」和说明。测速完成后状态行显示「正在进入 线路 · 延迟」并进入；点「线路与更新」可以暂停自动进入。
- **进站画面**（`src/inject/remote.js`）：和启动页最后一帧完全一样的静止画面（同一张图、同一位置、同一条进度条），站点加载好后原地淡出，所以切换时画面不动。只用样式表画在 `html::before / ::after` 上，不往页面里插元素（站点是 React 应用，注水前多出元素会整页重绘）。同一次打开应用只出现一次；最短 0.35 秒，DOM 就绪后最多再等 0.8 秒，最长 4 秒。`test/brand-lockup.test.mjs` 检查两边的图形和位置一致。
- **关于页**：品牌说明、客户端额外提供的功能、源代码入口（GitHub，MIT 许可）。

## 客户端额外提供的功能

网页端已有的播放、全屏、画中画、投屏等功能，客户端不重复实现。客户端额外提供的是需要应用自己参与的部分：

- **应用里的站点外观**：只在应用里生效，网页版不变。隐藏网页才需要的首次访问免责卡片（启动页已经写了）和「手机客户端下载」卡片；手机上顶栏、底栏换成半透明毛玻璃，底栏一屏 5 个、按格滑动，当前一项有底色；去掉网页式的点击高亮。样式在 `src/inject/remote.js` 的 `APP_CSS`，站点组件上用 `data-app` 标记（header / tabbar / welcome）。
- **CKTV 播放器**（`src/player.html`）：站点播放视频时点工具条上的「播放器」，或在下载页点「播放」打开。单击显示控制栏、双击暂停；左右滑动调进度，左侧上下滑亮度、右侧上下滑音量；长按 2 倍速；倍速菜单、锁屏、画中画、续播。全屏时安卓横屏并隐藏系统栏（`window.CKTVNative`，见手机工程补丁），iPhone 用系统全屏播放器。
- **应用菜单**：站点页面左下角的菜单按钮（手机上在底部导航栏上方），随时可以刷新页面、回到首页、打开下载管理、切换线路、检查更新、复制本页链接、用浏览器打开、查看关于。站点完成加载之后才挂上，不影响站点的注水。
- **离线下载**：把视频保存到本机，断网也能播放。见上文「离线下载」。
- **线路测速与切换**：启动时并行测速选出最快的线路；「线路」标签页可以手动切换。线路响应异常时，顶部提示「切换线路」，一键打开。
- **断网提示**：断网时顶部提示，网络恢复后提示刷新。
- **线路异常提示**：30 秒内站点接口（`/api/`）连续 3 次返回 503、504 或网络错误，才提示「线路响应异常」；关闭提示后 10 分钟内不再提示。
- **更新提示卡片**：站点页面里收到新版本时，右下角（手机上是底部）弹出卡片。点「稍后」后，本次打开应用期间不再提示同一个版本。
- **切回前台检查更新**：离开应用超过 1 分钟再回来，距离上次检查超过 30 分钟，才在后台检查一次。

## 手机图标

手机图标就是网站标志（`public/icon.svg`、`public/logo.png`），不另外设计。源文件在 `assets/mobile-icons/`：

- iOS：整块方形铺满、不透明，圆角由系统加。
- 安卓：三层自适应图标（深色渐变背景、标志、单色主题层）。网站标志的 512 单位正好映射到系统露出的中间 72dp，所以不管手机把图标裁成什么形状，看到的都和网站标志一样。

改了网站标志后重新生成（需要 Playwright）：`NODE_PATH=$(npm root -g) node scripts/make-mobile-icons.mjs`

## 手机工程的补丁（图标、状态栏）

`src-tauri/gen/` 不进仓库，CI 每次用 `tauri android init` / `tauri ios init` 重新生成。生成的工程用 Tauri 默认图标（蓝黄两个圆环），安卓模板还是全面屏、浅色主题，网页会画到状态栏下面。所以 init 之后要执行：

```bash
node scripts/patch-mobile.mjs android   # 图标、深色主题、内容避开状态栏/导航栏/刘海/输入法
node scripts/patch-mobile.mjs ios       # AppIcon 每一格换成 CKTV 图标
```

发布流程和安卓构建流程里已经加上了。本地生成工程后（例如 `pnpm tauri android dev` 之前）也要执行一次。生成的工程和预期不一样时脚本直接失败，不会打出带默认图标的包。

## 本地开发

前置条件：Node 22、pnpm 10、Rust stable。Linux 还需要 Tauri 官方文档列出的 WebKitGTK 4.1 等依赖。

```bash
cd client
pnpm install

pnpm dev            # 桌面开发窗口（tauri dev）
pnpm build          # 只构建界面到 dist/
pnpm test           # 纯函数和脚本的测试
pnpm check:version  # 检查版本号一致，README 的版本信息也要同步

cd src-tauri
cargo test
cargo clippy --all-targets -- -D warnings
```

## 版本号

版本号以 `package.json` 为准，同步到 `tauri.conf.json`、`Cargo.toml` 和 `Cargo.lock`。**每次更新都要用新的版本号和新的标签**，不要复用旧标签，也不要把版本号改小。下面标记之间的「版本信息」由脚本生成，不要手改。

<!-- version:start -->

<!-- 由 scripts/sync-version.mjs 生成，不要手改 -->

当前版本：**1.2.5**，标签 `app-v1.2.5`。

下一次升版本，在 `client` 目录运行（新版本号必须比它大）：

```bash
node scripts/sync-version.mjs <新版本号> --after app-v1.2.5
```

<!-- version:end -->

`--after` 填上一个正式发布的标签，也就是「版本信息」里写的当前标签。新版本号必须比它大，否则不写入。原因是应用只会安装比当前版本大的版本：版本号倒退或停在原地，老用户就收不到更新。CI 发布时还会再检查一次：标签和版本号一致，README 的版本信息和版本号一致，并且比上一个正式发布大。

## 不需要配置密钥

这个项目不需要任何签名密钥，也不需要在 GitHub 里配置 Secrets。各平台的安装包这样处理：

- **macOS**：使用临时签名（ad-hoc），没有开发者证书，也没有公证。第一次打开需要在「系统设置 → 隐私与安全性」里点「仍要打开」。
- **Windows**：安装程序未签名。SmartScreen 提示时点「更多信息」→「仍要运行」。
- **Linux**：AppImage 不需要签名。
- **安卓**：使用仓库里公开的签名密钥 `signing/cktv-android-public.jks`，口令也是公开的。它保证每个版本都用同一个密钥签名，所以覆盖安装可以成功。**任何人都能用这个密钥签名，它不能证明安装包来自我们**，只保证版本之间能覆盖安装。
- **iOS**：构建未签名的 IPA，用户在 AltStore 里用自己的 Apple ID 重新签名后安装。

仓库变量 `CN_MIRROR_BASE`（可选）是国内下载线路的根地址，例如 `https://tv.chuankangkk.top/cktv`。设置后，发布时会自动加上版本标签，每个安装包的国内线路是 `<根地址>/app-v<版本号>/<文件名>`，变量只需要设置一次。**发布流程不会上传国内线路的文件**，需要自己把同名文件同步到 `<根地址>/app-v<版本号>/`。地址的域名必须在白名单里，否则发布失败。没有设置时，应用只提供 GitHub 线路。

## 发布流程

```bash
cd client

# 1. 改版本号并提交：--after 填上一个正式发布的标签（「版本信息」里的当前标签）
#    README 的版本信息会一起更新
node scripts/sync-version.mjs <新版本号> --after <上一个标签>
git commit -am "chore(client): 版本 <新版本号>"

# 2. 推荐打注释标签（git tag -a）：标签注释就是更新说明的第一段。轻量标签也能发布，但更新说明只有默认文案
git tag -a app-v<新版本号> -m "- 更新说明"
git push origin app-v<新版本号>
```

推送标签后，`.github/workflows/app-release.yml` 会依次运行：

1. **verify**：检查版本号与标签一致、README 的版本信息同步、比上一个正式发布大，并运行脚本测试；创建草稿 Release。标签是注释标签时用它的注释作更新说明，是轻量标签时用默认文案。
2. **desktop**：macOS（通用版）、Windows、Linux 并行构建，安装包上传到草稿。
3. **android**：构建 APK，用公开密钥签名，上传到草稿。
4. **ios**：构建未签名的 IPA，上传到草稿。
5. **publish**：生成 `update.json`、`altstore.json`、图标和 `release-notes.md`（标签注释、下载表格和 SHA-256），上传后把草稿改为正式发布。`releases/latest` 指向这个正式版本，应用和 AltStore 都从这里读取。

五个平台的安装包必须全部生成，`publish` 才会运行。如果有任务失败，Release 会保持草稿状态，应用和 AltStore 都读不到新版本，去 Actions 页面查看失败的任务。

## 应用里的更新怎么工作

- 清单地址是 `https://github.com/1837620622/ck_tv/releases/latest/download/update.json`，和 Release 一起发布。
- 启动约 12 秒后做第一次检查，之后按设置的间隔（6、12、24 小时或每周）后台检查，设置里可以关闭自动检查。切回前台时，距离上次检查超过 30 分钟才会再检查一次。
- 发现新版本时，主窗口右下角弹出提示（站点页面里也会显示），托盘图标显示「有新版本」。点「跳过这个版本」之后，只有更高的版本才会再提醒。
- **下载线路**：应用会判断所在地区（访问 `https://www.cloudflare.com/cdn-cgi/trace`，4 秒超时）。
  - 海外用户（非 iOS）：直接在浏览器里打开 GitHub 下载。
  - 中国大陆用户：弹出线路选择，配置了 `CN_MIRROR_BASE` 时推荐国内线路；没有配置时只有 GitHub，并提示国内线路暂未提供。
  - 无法判断地区，以及所有 iOS 用户：弹出线路选择，不推荐任何线路。
  - 香港、澳门、台湾按海外处理。
- **安装**：桌面端下载后手动安装；安卓下载 APK 后覆盖安装；iOS 在 AltStore 里添加源后安装。

## 决定和待办

- **下载功能的措辞（已改）**：启动页、关于页和下载页写的是：应用不内置、不传播任何影视资源；下载的视频只保存在这台设备上，仅供个人离线观看。**站点的免责声明还写着「本站不存储任何视频资源」「视频在对方服务器，本站不留副本」**（写在根目录 `src/lib/config.ts`、`src/app/layout.tsx`、`src/components/AgeGate.tsx`、`src/components/SiteProvider.tsx`、`src/components/WelcomeModal.tsx` 里，站点就在这个仓库里）。站点本身确实不存储视频，但客户端的「下载本集」会把视频存到用户自己的设备上，这些措辞要不要改，需要项目负责人决定，没有擅自修改。
- **下载方式（已定）**：网页只能把地址和名称预填到下载页，开始下载必须由用户点「开始下载」。网页不能替用户写文件，所以需要用户确认。
- **iOS 方案（已定）**：推荐「添加到主屏幕」；需要离线下载的用户用 AltStore 安装未签名的 IPA。不做 TestFlight，因为它需要付费账号和签名密钥。
- **安卓签名（已定）**：使用公开密钥，只保证覆盖安装，不能证明安装包来自我们。将来换成自己保管的密钥后，旧版本不能直接覆盖安装，要先卸载。
