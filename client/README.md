# CKTV 客户端

把 CKTV 站点装进 macOS、Windows、Linux、Android 和 iOS 应用里。启动时自动测速选出最快的线路，带自动检查更新，还能把视频下载到本机离线播放。

界面是纯静态页面（无框架），原生层是 Tauri 2（Rust）。站点内容仍由服务器提供；只有用户自己点「下载」的视频才会保存在本机。

## 下载和安装

每次发布都会有新的版本号。最新版本和全部安装包都在 Release 页面：

- **最新版本（全部安装包）**：<https://github.com/1837620622/ck_tv/releases/latest>
- **构建记录（Actions）**：<https://github.com/1837620622/ck_tv/actions/workflows/app-release.yml>
- **固定地址（永远指向最新版）**
  - 应用读取的更新清单：<https://github.com/1837620622/ck_tv/releases/latest/download/update.json>
  - iPhone 的 AltStore 源：<https://github.com/1837620622/ck_tv/releases/latest/download/altstore.json>

安装包文件名里的 `<版本>` 是版本号，例如 `1.2.0`。

| 平台                             | 在最新版本页面里找           | 怎么安装                                                                                                                     |
| -------------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| macOS（Apple 芯片和 Intel 通用） | `CKTV_<版本>_universal.dmg`  | 打开 `.dmg`，把 CKTV 拖进「应用程序」。第一次打开提示「无法验证开发者」时，到「系统设置 → 隐私与安全性」底部点「仍要打开」。 |
| Windows                          | `CKTV_<版本>_x64-setup.exe`  | 运行安装程序。SmartScreen 提示时点「更多信息」→「仍要运行」。                                                                |
| Linux                            | `CKTV_<版本>_amd64.AppImage` | 加上执行权限（`chmod +x`）后直接运行。                                                                                       |
| 安卓                             | `CKTV_<版本>_android.apk`    | 允许安装未知来源的应用后安装。之后的版本直接覆盖安装。                                                                       |
| iPhone / iPad                    | 不能直接安装                 | 见下一节。                                                                                                                   |

最低系统版本：macOS 11、iOS 14。

## iPhone 和 iPad

苹果不允许未签名的应用直接安装，所以 iPhone 上没有「下载安装包就能装」的办法。下面三种方式里，推荐第一种。

| 方式                         | 要做什么                                                                                               | 能用的功能                           | 限制                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------ | ---------------------------------------------------------------------------- |
| **网页添加到主屏幕（推荐）** | 用 Safari 打开站点，点「分享」→「添加到主屏幕」                                                        | 站点的在线功能：播放、全屏、切换线路 | 没有离线下载，没有应用内的更新提示                                           |
| AltStore（或 SideStore）     | 在电脑上安装 AltStore，用免费的 Apple ID 安装 CKTV 的 IPA。在 AltStore 里添加上面的 `altstore.json` 源 | 完整客户端，包括离线下载             | 免费 Apple ID 签名的应用 7 天过期，需要定期刷新；免费账号同时只能装 3 个应用 |
| TestFlight                   | 需要付费的 Apple 开发者账号（每年 99 美元）和签名密钥                                                  | 完整客户端                           | 要在仓库里配置签名密钥，和「不需要配置密钥」的做法冲突，目前没有做           |

**推荐**：先用「添加到主屏幕」。它不需要账号、签名或电脑，一步就能完成，对用户来说什么都不用装。需要离线下载的用户，再用 AltStore 安装 IPA。

AltStore 的源随每次正式发布更新，还没有在真机上完整安装过，见下文「验证状态」。

## 离线下载（电脑和手机都有）

- **从网页下载**：站点在播放视频时，左下角会出现「下载本集」和「列表」。点「下载本集」会打开下载页，并把视频地址和名称填好，**不会直接开始下载**，需要在下载页点「开始下载」。
- **手动粘贴**：下载页的「视频地址」可以粘贴 `.mp4` 直链，也可以粘贴 `.m3u8` 分片地址。分片视频自动选最高画质，最多 4 个分片同时下载，AES-128 加密的分片在本机解密。SAMPLE-AES 等 DRM 加密不支持，会直接报错，不会留下残缺的文件。
- **保存位置**：应用自己的数据目录，不进入系统相册、「文件」或下载文件夹。卸载应用时一并删除。
- **播放**：下载页里可以播放并全屏。电脑上还能用系统播放器打开，手机上没有这个入口。
- **手机**：下载页在主窗口里打开，顶部有返回按钮，返回后回到原来看的视频。
- **限制**：地址最长 8192 个字符，只接受 `http://` 和 `https://`。播放列表最大 4 MB，单个分片最大 64 MB，分片最多 2 万个。失败或取消的可以「重新下载」。删除要点两次，避免误删。
- 只保存你有权保存的内容。

## 安全模型

- 站点页面是远程内容，**不能调用任何原生命令**。它只能通过 `cktv://` 地址请求应用做下面几件事，其它地址一律忽略：

  | 地址                                                   | 作用                                                         |
  | ------------------------------------------------------ | ------------------------------------------------------------ |
  | `cktv://updater`（可加 `?tab=update\|servers\|about`） | 打开更新中心                                                 |
  | `cktv://home`                                          | 回到启动页                                                   |
  | `cktv://resume`                                        | 切回前台时检查更新（距离上次检查超过 30 分钟，才真的去检查） |
  | `cktv://downloads`                                     | 打开下载列表                                                 |
  | `cktv://download?url=…&title=…`                        | **只打开下载页，并填好地址和名称，不会开始下载**             |

- **下载只能预填，不能直接开始**。站点页面的内容不可信，不能让它替用户写文件。开始下载必须由用户在下载页点「开始下载」。这是有意的设计，不要为了省一步改成自动开始。
- 站外链接交给系统浏览器打开，不在应用里跳转。
- 注入脚本只在应用的 WebView 里运行，站点源码不因此改动；界面放在 Shadow DOM 里，不影响站点自己的样式。
- 原生命令 `open_external` 和更新清单里的下载地址，只允许 `github.com`、`objects.githubusercontent.com`、`release-assets.githubusercontent.com`、`tv.chuankangkk.top`、`ck-tv.pages.dev` 及其子域名，并且必须是 `https://`。
- 线路只能是 `https://` 的官方线路或用户添加的线路（调试版额外允许 localhost，方便联调）。
- 应用不替换自己：更新只是提示和下载链接，安装包由用户自己安装。Release 说明里有每个安装包的 SHA-256，下载后可以核对。

## 启动与开场

- **启动页**（`src/index.html`）：标志的圆环描边绘制、播放按钮弹出，字标逐字出现，写明「非盈利、免费、无偿提供」。测速完成后自动进入线路；点「线路与更新」可以暂停自动进入。
- **站点开场**（`src/inject/remote.js`）：应用启动后第一次进入站点时，盖一层品牌画面，页面加载完成后淡出。同一次打开应用只播一次，刷新页面不再播；系统开启「减少动态效果」时直接跳过；最多 3.5 秒，页面还没加载完也会先退场，至少停留 1.6 秒。
- **关于页**：品牌说明、客户端额外提供的功能、源代码入口（GitHub，MIT 许可）。

## 客户端额外提供的功能

网页端已有的播放、全屏、画中画、投屏等功能，客户端不重复实现。客户端额外提供的是需要应用自己参与的部分：

- **离线下载**：把视频保存到本机，断网也能播放。见上文「离线下载」。
- **线路测速与切换**：启动时并行测速选出最快的线路；「线路」标签页可以手动切换。线路响应异常时，顶部提示「切换线路」，一键打开。
- **断网提示**：断网时顶部提示，网络恢复后提示刷新。
- **线路异常提示**：30 秒内站点接口（`/api/`）连续 3 次返回 503、504 或网络错误，才提示「线路响应异常」；关闭提示后 10 分钟内不再提示。
- **更新提示卡片**：站点页面里收到新版本时，右下角（手机上是底部）弹出卡片。点「稍后」后，本次打开应用期间不再提示同一个版本。
- **切回前台检查更新**：离开应用超过 1 分钟再回来，距离上次检查超过 30 分钟，才在后台检查一次。

## 本地开发

前置条件：Node 22、pnpm 10、Rust stable。Linux 还需要 Tauri 官方文档列出的 WebKitGTK 4.1 等依赖。

```bash
cd client
pnpm install

pnpm dev            # 桌面开发窗口（tauri dev）
pnpm build          # 只构建界面到 dist/
pnpm test           # 纯函数和脚本的测试
pnpm check:version  # 检查 package.json、tauri.conf.json、Cargo.toml 版本一致

cd src-tauri
cargo test
cargo clippy --all-targets -- -D warnings
```

## 版本号

版本号以 `package.json` 为准，同步到 `tauri.conf.json`、`Cargo.toml` 和 `Cargo.lock`。**每次更新都要用新的版本号和新的标签**，不要复用旧标签，也不要把版本号改小。

```bash
cd client
node scripts/sync-version.mjs 1.2.0 --after app-v1.1.0
```

`--after` 填上一个正式发布的标签。新版本号必须比它大，否则不写入。原因是应用只会安装比当前版本大的版本：版本号倒退或停在原地，老用户就收不到更新。CI 发布时还会再检查一次：标签和版本号一致，并且比上一个正式发布大。

## 不需要配置密钥

这个项目不需要任何签名密钥，也不需要在 GitHub 里配置 Secrets。各平台的安装包这样处理：

- **macOS**：使用临时签名（ad-hoc），没有开发者证书，也没有公证。第一次打开需要在「系统设置 → 隐私与安全性」里点「仍要打开」。
- **Windows**：安装程序未签名。SmartScreen 提示时点「更多信息」→「仍要运行」。
- **Linux**：AppImage 不需要签名。
- **安卓**：使用仓库里公开的签名密钥 `signing/cktv-android-public.jks`，口令也是公开的。它保证每个版本都用同一个密钥签名，所以覆盖安装可以成功。**任何人都能用这个密钥签名，它不能证明安装包来自我们**，只保证版本之间能覆盖安装。
- **iOS**：构建未签名的 IPA，用户在 AltStore 里用自己的 Apple ID 重新签名后安装。

仓库变量 `CN_MIRROR_BASE`（可选）是国内下载线路的地址前缀，例如 `https://tv.chuankangkk.top/cktv/app-v1.2.0`。设置后，发布时会为每个安装包生成国内线路地址，格式是 `<前缀>/<文件名>`。**发布流程不会上传国内线路的文件**，需要自己把同名文件同步到那里。地址的域名必须在白名单里，否则发布失败。没有设置时，应用只提供 GitHub 线路。

## 发布流程

```bash
cd client

# 1. 改版本号（--after 填上一个正式发布的标签）并提交
node scripts/sync-version.mjs 1.2.0 --after app-v1.1.0
git commit -am "chore(client): 版本 1.2.0"

# 2. 打注释标签：标签注释就是更新说明的第一段
git tag -a app-v1.2.0 -m "- 修复全屏拖动进度"
git push origin app-v1.2.0
```

推送标签后，`.github/workflows/app-release.yml` 会依次运行：

1. **verify**：检查版本与标签一致，并且比上一个正式发布大；创建草稿 Release。
2. **desktop**：macOS（通用版）、Windows、Linux 并行构建，安装包上传到草稿。
3. **android**：构建 APK，用公开密钥签名，上传到草稿。
4. **ios**：构建未签名的 IPA，上传到草稿。
5. **publish**：生成 `update.json`、`altstore.json`、图标和 `release-notes.md`（标签注释、下载表格和 SHA-256），上传后把草稿改为正式发布。`releases/latest` 指向这个正式版本，应用和 AltStore 都从这里读取。

五个平台的安装包必须全部生成，`publish` 才会运行。如果有任务失败，Release 会保持草稿状态，应用和 AltStore 都读不到新版本，去 Actions 页面查看失败的任务。

## 应用里的更新怎么工作

- 清单地址是 `https://github.com/1837620622/ck_tv/releases/latest/download/update.json`，和 Release 一起发布。
- 启动约 12 秒后做第一次检查，之后按设置的间隔（6、12、24 小时或每周）后台检查，设置里可以关闭自动检查。切回前台时，距离上次检查超过 30 分钟才会再检查一次。
- 发现新版本时，主窗口右下角弹出提示（站点页面里也会显示），托盘图标显示「有新版本」。点「跳过这个版本」之后，只有更高的版本才会再提醒。
- **下载线路**：应用会判断所在地区（访问 `https://www.cloudflare.com/cdn-cgi/trace`，4 秒超时）。
  - 海外用户（非 iOS）：直接在浏览器里打开 GitHub 下载。
  - 中国大陆用户：弹出线路选择，配置了 `CN_MIRROR_BASE` 时推荐国内线路；没有配置时只有 GitHub，并提示国内线路暂未提供。
  - 无法判断地区，以及所有 iOS 用户：弹出线路选择，不推荐任何线路。
  - 香港、澳门、台湾按海外处理。
- **安装**：桌面端下载后手动安装；安卓下载 APK 后覆盖安装；iOS 在 AltStore 里添加源后安装。

## 验证状态

以下在 Linux 上实际运行过（模拟数据，没有原生层）：

- **前端**：`pnpm test` 75 项全部通过；`pnpm build` 通过；ESLint（界面、脚本、测试，零警告）和 Prettier 通过。
- **乱码扫描**：75 个文本文件（包括构建产物 `dist/`），没有非法 UTF-8、替换字符或乱码。
- **Rust**：`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings` 和 `cargo test`（33 项）通过。
- **浏览器预览**：下载页在桌面（1280×800）和手机（390×844）宽度下的列表、地址校验、横向滚动和播放提示；站点预填（带参数打开、收到事件、都不会自动开始）；站点上下载条的显示、位置、关闭，以及点击后的文字「已打开下载页」。共 31 项检查全部通过。

**还没有验证**：

- 发布流水线（`app-release.yml`）还没有在 GitHub 上完整运行过。第一次运行可能需要调整，以 Actions 页面的结果为准。
- 五个平台的安装包没有在真实设备上安装和运行。覆盖安装、更新下载、SHA-256 核对、AltStore 添加源和安装，都还没有在真机上完整走过。
- 真实 WebView 里的 `cktv://` 拦截、刘海和底部手势条的安全区布局、全屏视频、离线下载的长时间运行，没有完整验证。
- 国内线路还没有配置（没有 `CN_MIRROR_BASE`），中国大陆用户目前只能使用 GitHub 线路。
- `src-tauri/gen/`（Android 和 Apple 工程）不提交，由 CI 里的 `tauri android init --ci` 和 `tauri ios init --ci` 生成。

## 待确认

- **下载功能的措辞**：启动页、关于页写着「不内置、不存储、不传播任何影视资源」，站点的免责声明写着「不存储、不留副本」。下载功能会在本机保存副本，这些说法需要和下载功能一起确认后再改。
- **iOS 方案**：目前推荐「添加到主屏幕」，AltStore 作为离线下载的备选。是否采用，需要确认。
- **安卓签名**：公开密钥只保证覆盖安装，不能证明安装包来自我们。如果需要证明来源，要换成自己保管的密钥（见「不需要配置密钥」）。
